# Generated Kubernetes manifests

In `target: k8s` mode you **never write Kubernetes YAML by hand**. Every
`wrapper up` (and `wrapper agent add`) regenerates plain manifests from the
same source of truth the compose generator uses — `agents/*/agent.yaml` plus
the `k8s:` block of `wrapper.yaml`:

```
k8s/                      # gitignored — a build artifact, not source
├── namespace.yaml        # Namespace + ServiceAccount
└── agents/<name>.yaml    # per agent: PVC + Deployment
```

The generator is `packages/cli/src/manifests.ts`. If you want different
defaults (resources, storage size, labels), change it there — edits to the
generated files are lost on the next regeneration (each file says so in its
header).

## What each agent gets

Annotated example of a generated `k8s/agents/<name>.yaml` (placeholders in
`<...>`):

```yaml
# GENERATED by `wrapper` — do not edit by hand.
apiVersion: v1
kind: PersistentVolumeClaim          # sessions, cron jobs, memory, workspace
metadata:
  name: agent-<name>-data
  namespace: <namespace>
  labels: { app: wrapper-agent, agent: <name> }
spec:
  accessModes: [ReadWriteOnce]
  storageClassName: <storageClass>   # wrapper.yaml k8s.storageClass
  resources: { requests: { storage: 1Gi } }
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: agent-<name>
  namespace: <namespace>
  labels: { app: wrapper-agent, agent: <name> }
spec:
  replicas: 1
  # Recreate, never RollingUpdate: two live pods would both hold Slack
  # Socket Mode connections and split incoming events between them.
  strategy: { type: Recreate }
  selector: { matchLabels: { app: wrapper-agent, agent: <name> } }
  template:
    metadata:
      labels: { app: wrapper-agent, agent: <name> }
    spec:
      serviceAccountName: <serviceAccount>
      nodeSelector: { kubernetes.io/arch: <arch> }   # matches image platform
      securityContext:                # pod-level hardening
        runAsNonRoot: true
        runAsUser: 1000
        runAsGroup: 1000
        fsGroup: 1000                 # makes the PVC writable by the pod user
        seccompProfile: { type: RuntimeDefault }
      containers:
        - name: agent
          image: <registry>/<repoPrefix>/agents/<name>:latest
          imagePullPolicy: Always
          envFrom:
            - secretRef: { name: agent-<name>-env }   # synced from agents/<name>/.env
          env:
            - { name: AGENT_DIR, value: /app/agent }
            - { name: DATA_DIR, value: /data }
            - { name: AWS_REGION, value: <awsRegion> }        # only if set (AWS)
            - { name: LANGFUSE_BASEURL, value: <langfuseBaseUrl> }
          volumeMounts:
            - { name: data, mountPath: /data }
            - { name: tmp, mountPath: /tmp }   # rootfs is read-only; /tmp is the
          securityContext:                     # only scratch space
            readOnlyRootFilesystem: true
            allowPrivilegeEscalation: false
            capabilities: { drop: [ALL] }
          resources:
            requests: { cpu: 100m, memory: 256Mi }
            limits: { cpu: "1", memory: 1Gi }
      volumes:
        - name: data
          persistentVolumeClaim: { claimName: agent-<name>-data }
        - name: tmp
          emptyDir: {}
```

Things deliberately **absent**:

- **No Service, no Ingress.** Agents are outbound-only (Slack Socket Mode);
  nothing in the cluster needs to reach them.
- **No Secret manifest.** `agent-<name>-env` is created *imperatively* at
  deploy time — `kubectl create secret generic --from-env-file=agents/<name>/.env
  --dry-run=client -o yaml | kubectl apply` — so secret material never lands in
  a file that could be committed. The local `.env` is the source of truth;
  `wrapper restart <name>` re-syncs it before rolling.

## The image

Clusters can't bind-mount your laptop, so the agent's files are **baked into
its image**: a generated one-line Dockerfile layers `COPY agents/<name>
/app/agent` on top of either the shared runtime image or the agent's own
`Dockerfile` image (if it has one). Consequence: prompt/tool changes need
`wrapper up <name>` (rebuild + push + roll), while `.env` changes only need
`wrapper env set … && wrapper restart …`.

## Customizing beyond the generator

- **Defaults for everyone** (resources, PVC size, extra labels/annotations):
  edit `packages/cli/src/manifests.ts` and rerun `wrapper up`.
- **Live, out-of-band patches** — e.g. cloud IAM annotations on the
  ServiceAccount (AWS IRSA / GKE Workload Identity):

  ```bash
  kubectl -n <namespace> annotate serviceaccount <serviceAccount> \
    eks.amazonaws.com/role-arn=arn:aws:iam::<account>:role/<role>
  ```

  This is the intended pattern: the generator deliberately emits the
  ServiceAccount *without* such annotations, and `kubectl apply`'s three-way
  merge preserves fields it never managed — so regeneration/redeploy never
  strips your patch.
- **Recommended production add-ons** (not generated, see the deploy docs):
  a default-deny egress NetworkPolicy, encrypted StorageClass for the PVC,
  secret encryption at rest, image digest pinning.
